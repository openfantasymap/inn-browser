# LLM Integration for Dynamic Guest Generation

This game uses AI-powered guest generation via OpenRouter to create unique, contextually appropriate guests with dynamically generated stats and names.

## Features

- **AI-Generated Names**: Each guest gets a unique, thematically appropriate name based on their type
- **Dynamic Stats**: Guest stats (patience, gold, reputation, etc.) are generated by AI based on the guest archetype
- **Contextual Awareness**: The AI understands different guest types (peasant, wizard, knight, etc.) and generates appropriate stats
- **Automatic Fallback**: If LLM generation fails or is disabled, the system falls back to traditional random generation

## Setup

### 1. Get an OpenRouter API Key

1. Visit https://openrouter.ai/
2. Create an account
3. Go to https://openrouter.ai/keys
4. Generate a new API key

### 2. Configure the API Key

You can configure the API key in two ways:

#### Option A: Environment Variable (Recommended)
```bash
export OPENROUTER_API_KEY="your-api-key-here"
```

#### Option B: Django Settings
Edit `inn_project/settings.py` and replace the placeholder:
```python
OPENROUTER_API_KEY = 'your-api-key-here'
```

### 3. Choose Your Model

The default model is `meta-llama/llama-3.1-8b-instruct:free` (free tier).

You can change it via environment variable:
```bash
export OPENROUTER_DEFAULT_MODEL="meta-llama/llama-3.1-8b-instruct:free"
```

#### Recommended Models

**Free Models:**
- `meta-llama/llama-3.1-8b-instruct:free` - Good balance, free tier
- `google/gemini-2.0-flash-exp:free` - Fast, free tier
- `mistralai/mistral-7b-instruct:free` - Fast, free tier

**Paid Models (Better Quality):**
- `anthropic/claude-3.5-sonnet` - Best quality, very accurate
- `openai/gpt-4o-mini` - Good quality, affordable
- `google/gemini-pro-1.5` - Fast and capable

### 4. Enable/Disable LLM Generation

To disable LLM generation (use traditional random generation):
```bash
export USE_LLM_GUEST_GENERATION="false"
```

To enable (default):
```bash
export USE_LLM_GUEST_GENERATION="true"
```

## How It Works

### Guest Generation Flow

1. **Guest Type Selection**: A random guest type is selected (peasant, wizard, knight, etc.)
2. **LLM Name Generation**:
   - The AI generates a contextually appropriate name for the guest type
   - Example: A wizard might be named "Mystara", a peasant "Thomas"
   - Fallback: Uses traditional name pool if LLM fails
3. **LLM Stats Generation**:
   - The AI generates balanced stats based on the guest type
   - Considers: wealth level, patience, prestige, stay duration
   - Example: A noble has high gold, low patience, high reputation
   - Fallback: Uses traditional stat tables if LLM fails
4. **Validation**: All LLM-generated values are validated and constrained to game balance

### Guest Type Profiles

The AI understands these archetypes:

| Guest Type | Wealth | Patience | Reputation | Characteristics |
|-----------|--------|----------|------------|----------------|
| Peasant | Low | Medium | Low | Common folk, simple needs |
| Merchant | Medium | Low | Medium | Busy, expects good service |
| Noble | High | Very Low | High | Demanding, expects luxury |
| Adventurer | Medium | High | Medium | Patient, appreciates quality |
| Wizard | Very High | Medium | Very High | Scholarly, particular |
| Knight | Medium-High | Medium-High | High | Honorable, respectable |
| Ranger | Low-Medium | Very High | Medium | Independent, patient |

### Stat Ranges (AI-Generated)

- **Patience**: 30-100 (how quickly they get impatient)
- **Gold Per Tick**: 0.5-5.0 (income they generate)
- **Reputation Bonus**: 1-10 (prestige value)
- **Satisfaction**: 50-100 (starting satisfaction)
- **Stay Duration**: 30-120 seconds

## Troubleshooting

### Issue: Guests have traditional names/stats
**Solution**: Check if LLM is enabled and API key is set:
```python
from django.conf import settings
print(f"API Key Set: {bool(settings.OPENROUTER_API_KEY)}")
print(f"LLM Enabled: {settings.USE_LLM_GUEST_GENERATION}")
```

### Issue: API errors in logs
**Solution**:
1. Verify API key is correct
2. Check OpenRouter dashboard for rate limits
3. Try a different model
4. System will automatically fallback to traditional generation

### Issue: Slow guest generation
**Solution**:
1. Use faster free models like `google/gemini-2.0-flash-exp:free`
2. Reduce timeout in LLM service if needed
3. Consider disabling LLM for development

## Architecture

```
GameService._try_spawn_guest()
    ↓
LLMService.generate_guest_name(guest_type)
    ↓ (if enabled)
OpenRouter API → LLM → Unique Name
    ↓ (fallback on error)
Random Name Pool
    ↓
LLMService.generate_guest_stats(guest_type, name)
    ↓ (if enabled)
OpenRouter API → LLM → Balanced Stats
    ↓ (fallback on error)
Traditional Stat Tables
    ↓
Guest Created with Generated/Fallback Data
```
